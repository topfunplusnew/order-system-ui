# 批量开票客户金额改用后端计算字段

日期：2026-09-05

## 需求

批量开票订单合计金额应使用“销售是否含税”为含税的明细合计，不能继续把所有明细金额合并计算。后端订单接口已新增以下字段，前端不再使用 `allPayments` 推算客户可开票金额：

- `saleIncludeTaxTotal`：销售含税明细金额合计
- `customerInvoicedAmount`：客户当前已开票净额
- `customerRemainingInvoiceAmount`：客户当前剩余可开票金额

## 问题原因

前端批量开票流程曾使用 `allPayments`，并结合前端已有开票金额字段自行计算客户剩余可开票金额。由于前端订单明细数据不完整，计算结果可能包含不含税明细或与后端实际结果不一致。

## 实际修改

1. `SelectGoods.vue`
   - 销项批量开票的单行剩余金额直接读取 `customerRemainingInvoiceAmount`。
   - 客户勾选订单的操作金额直接累加 `customerRemainingInvoiceAmount`。
   - 销项订单合计列改为显示 `saleIncludeTaxTotal`，标题改为“销售含税明细合计”。
   - 移除客户金额计算中对 `allPayments` 和前端 `totalInvoiceAmount` 扣减逻辑的依赖。

2. `QueueInvoiceList.vue`
   - 客户订单分配金额直接使用 `customerRemainingInvoiceAmount`。
   - 客户发票生成金额使用后端返回的可开票金额，不再以 `allPayments` 作为计算基数。
