# 订单管理系统核心模块实体设计与数据库表设计

## 1. 设计范围

本文档面向毕业论文中的系统分析与数据库设计章节，仅覆盖以下业务范围：系统管理、用户信息管理、基础信息维护、订单管理、库存管理、库存明细、出差管理、序时明细账。其他模块暂不纳入本次实体设计与数据库表设计。

系统采用关系型数据库进行业务数据持久化，围绕“用户与权限、基础档案、订单业务、库存流转、出差用车、资金与往来台账”建立数据模型。各业务表统一保留主键、创建信息、逻辑删除、备注等公共字段，便于后续审计、查询与扩展。

## 2. 总体实体设计

### 2.1 实体分类

| 实体类别 | 主要实体 | 设计说明 |
| --- | --- | --- |
| 系统管理实体 | 菜单、字典类型、字典数据、系统参数、操作日志、登录日志 | 支撑系统配置、权限菜单、枚举字典和运行日志记录。 |
| 用户权限实体 | 用户、角色、部门、用户角色、角色菜单、角色部门 | 支撑用户登录、角色授权、数据权限与组织结构管理。 |
| 基础档案实体 | 客户、供应商、产品级别、银行卡、车辆、科目、仓库、车队、公司车辆、加油卡 | 作为订单、库存、出差、资金台账等业务单据的基础引用。 |
| 订单业务实体 | 订单主表、订单明细、调整单、运费单 | 记录客户订单、供应商供货、运输信息、货款与利润核算。 |
| 库存业务实体 | 入库主表、入库明细、出库记录、货物损坏记录、二次加工记录 | 记录货物入库、存货变化、正常发货、损坏与加工流转。 |
| 库存明细实体 | 库存台账、入库记录、出库记录、仓库资金变动、库存余额 | 从库存业务单据汇总形成查询与报表数据。 |
| 出差管理实体 | 出差申请、车辆派出、油卡消费、出差报销 | 管理员工出差、车辆使用、加油卡消费及费用报销。 |
| 序时明细账实体 | 运费科目明细账、客户科目余额、供应商科目余额 | 从订单、运费、收付款、库存等单据汇总形成财务查询视图。 |

### 2.2 核心实体关系

1. 用户与角色为多对多关系，通过用户角色关联表实现；角色与菜单为多对多关系，通过角色菜单关联表实现。
2. 部门与用户为一对多关系，一个部门下可拥有多个用户；部门本身采用树形结构保存上下级关系。
3. 客户、供应商可统一抽象为往来单位实体，通过单位类型区分客户与供应商，也可在业务展示层按类型拆分管理。
4. 订单主表与订单明细为一对多关系；订单明细引用供应商、产品级别、仓库等基础档案。
5. 订单与运费单为一对多关系，一笔订单可产生陆运、海运或其他类型运费记录。
6. 入库主表与入库明细为一对多关系；入库明细形成库存余额，后续出库记录扣减对应库存。
7. 出差申请与车辆派出、报销明细为一对多关系；车辆派出可关联加油卡消费记录。
8. 序时明细账以业务单据为数据来源，按科目、客户、供应商、车辆、仓库等维度汇总形成报表。

## 4. 系统管理模块设计

### 4.1 实体设计

系统管理模块主要负责系统运行支撑数据维护，包括菜单管理、字典管理、参数设置和日志管理。

| 子模块 | 实体 | 主要属性 | 说明 |
| --- | --- | --- | --- |
| 菜单管理 | 菜单 | 菜单名称、父菜单、路由地址、组件路径、权限标识、排序、状态 | 用于构建后台菜单树和按钮级权限。 |

| 日志管理 | 操作日志、登录日志 | 操作人员、请求地址、业务类型、登录账号、登录状态、IP 地址 | 记录系统访问、登录和业务操作轨迹。 |

## 9. 库存明细模块设计

### 9.1 实体设计

库存明细模块偏向查询与统计，数据来源于入库、出库、损坏、二次加工和仓库资金变动。设计时可采用“业务单据表 + 汇总视图/报表表”的方式，既保证原始单据可追溯，又提升报表查询效率。

| 子模块 | 设计对象 | 数据来源 | 说明 |
| --- | --- | --- | --- |
| 库存台账 | inventory_ledger | 入库、出库、损坏、加工 | 按时间记录每一次库存数量和金额变动。 |
| 入库记录 | inventory_main、inventory_detail | 入库单 | 查询历史入库。 |
| 出库记录 | ex_warehouse | 出库单 | 查询历史出库。 |
| 仓库资金变动明细 | storehouse_fund_detail | 库存金额变化 | 按仓库记录资金增减。 |
| 库存余额表 | inventory_balance | 库存明细汇总 | 按仓库、产品、供应商汇总当前余额。 |

## 14. 数据完整性与业务规则

1. 订单号、产品级别编码、车牌号、加油卡号等关键业务编码应保持唯一，避免重复业务数据。
2. 客户和供应商统一存放在往来单位表中，通过 `company_type` 字段区分，便于后续往来账统一统计。
3. 订单明细中的数量、吨位、货款、运费、利润等金额字段应使用 `DECIMAL` 类型，避免浮点精度问题。
4. 入库明细的 `stock_number` 表示当前可用库存，出库、损坏、二次加工均应扣减或调整该字段。
5. 出库记录必须关联库存明细，保证每次库存减少均可追溯到原始入库批次。
6. 出差报销必须关联出差申请，油卡消费优先关联派车单，确保车辆、人员、费用之间可追溯。
7. 财务类汇总表可由定时任务或报表查询实时生成，来源单据编号和来源类型必须保留，便于穿透查询。
8. 业务表采用逻辑删除，不直接物理删除历史单据，以满足审计和论文系统数据追溯要求。

## 15. 小结

本数据库设计以订单业务为核心，以基础档案为支撑，以库存流转、出差用车和财务序时账为扩展，形成了较完整的业务数据模型。系统管理和用户权限模块保障系统安全运行；基础信息维护模块为订单、库存、出差等业务提供统一主数据；订单管理与库存管理模块记录核心经营过程；库存明细和序时明细账模块则面向统计分析与财务核算。通过主外键关系、唯一约束、普通索引和逻辑删除机制，可以较好地满足毕业论文系统在数据完整性、可追溯性和查询效率方面的设计要求。
