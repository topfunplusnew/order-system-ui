# requirements/ — 新需求记录目录

本目录用于**记录新需求**，是后续开发、验收、归档的原始依据。

## 目录约定

- 每批需求以**一个按日期命名的 Markdown 文件**记录，例如：
  - `2026-08-16-功能描述.md`
- 同一天有多批独立需求时，追加后缀区分，例如：
  - `2026-08-16-功能描述-资金变动.md`
- 记录格式参考 `_template.md`，与 `todo/` 目录的历史文档保持同一风格。

## 记录规范（重要）

1. **编号清晰**：每个需求以 `1、2、3...` 编号，一条一议，方便逐项落实。
2. **字段与接口明确**：涉及新增字段、接口变更时，必须写清字段名、接口地址、APIfox 链接（项目铁律：APIfox 驱动，杜绝主观臆测）。
3. **验收口径**：每个需求标注状态，最终交付时明确：
   - `已实现` / `待后端` / `待联调` / `待确认是否需求`
   - 字段为空类问题定位层级：`后端未返回` / `前端字段映射错误` / `展示格式化错误`
   - 按钮缺失类问题结论：`回归缺陷` / `历史未实现`
4. **风险标记**：对"后端可能未提供字段/接口"的项显式标记，避免前端误改。
5. **开发前提**：需求落地前，先检索库内现存逻辑（组件、方法、常量）尽量复用；金额相关逻辑必须使用 `mathjs`。

## 配套 Skill

项目内已提供 `requirement-recorder` Skill（`.cursor/skills/requirement-recorder/SKILL.md`），负责新需求的分流处理：
- 收到需求先确认是否为新需求；
- 是 → 按本目录规范记录（`_template.md`）；
- 否 → 直接实施修改。
建议在 Cursor/Agent 中启用该 Skill 后使用本目录。

## 文件顶部变更注释规范

**凡是修改了某个文件，都必须在该文件顶部添加"变更记录"注释**，说明本次改了什么，格式为：

```vue
<!--
	变更记录（每次需求变更在此追加，最新在上；格式：日期 - 改了什么）：
	- [YYYY-MM-DD] 本次改动说明。
	历史：
	- [YYYY-MM-DD] 历史改动说明。
-->
```

- 新变更记录加在最上方，已有记录保留为"历史"，不删除；
- 新增文件同样在顶部带一条 `[日期] 新建` 变更记录；
- 该规范由 `requirement-recorder` Skill 强制执行。

## 与 todo/ 的关系

- `todo/`：历史需求文档（2026-03 至 2026-04），已归档的旧记录。
- `requirements/`：**当前及今后的新需求记录**，是新需求的第一落点。

## 使用流程

1. 用户提出新需求 → 在本目录新建/追加当日文件（按 `_template.md`）。
2. 需求清单整理完毕 → 开发前与用户确认每条需求的验收口径。
3. 开发完成 → 更新各条目的状态，并同步到 `changelog/` 与提交信息。
