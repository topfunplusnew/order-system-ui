# 校验方法统一调用方案

## 1. 方案概述

### 1.1 现状分析
当前项目中，表单校验方法分散在各个组件中，存在以下问题：
- **重复代码**：相同的校验逻辑在多个组件中重复实现
- **维护困难**：校验规则变更需要修改多个文件
- **不一致性**：不同组件的校验规则可能存在差异
- **代码冗余**：每个组件都需要编写大量的校验函数

### 1.2 目标
- 统一校验方法管理
- 减少代码重复
- 提高维护效率
- 保证校验规则一致性

## 2. 技术方案

### 2.1 核心架构

```
┌─────────────────────────────────────────┐
│            业务组件                      │
│  ┌─────────────────────────────────────┐ │
│  │          引入校验方法                │ │
│  │  import { validationRules,          │ │
│  │          validatePhone } from       │ │
│  │          '@/api/tool'               │ │
│  └─────────────────────────────────────┘ │
│                    ↓                    │
│  ┌─────────────────────────────────────┐ │
│  │        配置表单校验规则              │ │
│  │  rules: {                           │ │
│  │    phone: validationRules.phone     │ │
│  │  }                                  │ │
│  └─────────────────────────────────────┘ │
└─────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────┐
│          @/api/tool/index.js            │
│  ┌─────────────────────────────────────┐ │
│  │        校验方法集合                  │ │
│  │  - validatePhone                    │ │

│  └─────────────────────────────────────┘ │
│  ┌─────────────────────────────────────┐ │
│  │        预设规则集合                  │ │
│  │  validationRules: {                 │ │
│  │    phone: [...],                    │ │

│  │  }                                  │ │
│  └─────────────────────────────────────┘ │
└─────────────────────────────────────────┘
```

### 2.2 校验方法分类

#### 2.2.1 基础校验方法
- `validatePhone` - 手机号校验
- `validateAmount` - 金额校验
- `validateEmail` - 邮箱校验
- `validateIdCard` - 身份证校验
- `validateBankCard` - 银行卡校验

#### 2.2.2 数值类校验
- `validatePositiveInteger` - 正整数校验
- `validateNonNegativeInteger` - 非负整数校验
- `validateRange(min, max)` - 数值范围校验

#### 2.2.3 字符串类校验
- `validateUsername` - 用户名校验
- `validatePassword` - 密码强度校验
- `validateChineseName` - 中文姓名校验
- `validateLength(min, max)` - 长度校验

#### 2.2.4 网络类校验
- `validateUrl` - URL地址校验
- `validateIp` - IP地址校验

#### 2.2.5 预设规则集合
- `validationRules.phone` - 手机号完整规则
- `validationRules.amount` - 金额完整规则
- `validationRules.email` - 邮箱完整规则
- 其他预设规则...

## 3. 使用方法

### 3.1 直接使用预设规则（推荐）

```javascript
// 1. 引入预设规则
import { validationRules } from '@/api/tool';

export default {
  data() {
    return {
      rules: {
        // 直接使用预设规则
        phone: validationRules.phone,
        amount: validationRules.amount,
        email: validationRules.email,
        
        // 组合使用
        companyName: [
          validationRules.required,
          { min: 2, max: 50, message: '公司名称长度在2-50个字符', trigger: 'blur' }
        ]
      }
    };
  }
};
```

### 3.2 使用单个校验方法

```javascript
// 1. 引入具体的校验方法
import { validatePhone, validateAmount } from '@/api/tool';

export default {
  data() {
    return {
      rules: {
        phone: [
          { required: true, message: '请输入手机号', trigger: 'blur' },
          { validator: validatePhone, trigger: 'blur' }
        ],
        amount: [
          { required: true, message: '请输入金额', trigger: 'blur' },
          { validator: validateAmount, trigger: 'blur' }
        ]
      }
    };
  }
};
```

### 3.3 使用工厂函数

```javascript
// 1. 引入工厂函数
import { validateLength, validateRange } from '@/api/tool';

export default {
  data() {
    return {
      rules: {
        description: [
          { required: true, message: '请输入描述', trigger: 'blur' },
          { validator: validateLength(10, 200), trigger: 'blur' }
        ],
        score: [
          { required: true, message: '请输入分数', trigger: 'blur' },
          { validator: validateRange(0, 100), trigger: 'blur' }
        ]
      }
    };
  }
};
```

### 3.4 自定义校验组合

```javascript
// 1. 引入多个校验方法
import { validatePhone, validationRules } from '@/api/tool';

export default {
  data() {
    return {
      rules: {
        // 使用预设规则
        primaryPhone: validationRules.phone,
        
        // 自定义组合（可选手机号）
        secondaryPhone: [
          { validator: this.validateOptionalPhone, trigger: 'blur' }
        ]
      }
    };
  },
  methods: {
    // 自定义可选手机号校验
    validateOptionalPhone(rule, value, callback) {
      if (!value) {
        // 不是必填，直接通过
        callback();
        return;
      }
      // 有值时使用标准手机号校验
      validatePhone(rule, value, callback);
    }
  }
};
```

## 4. 迁移指南

### 4.1 现有组件改造步骤

#### 步骤1：分析现有校验规则
```javascript
// 改造前：自定义校验函数
const validateRegion = (rule, value, callback) => {
  if (this.form.province && this.form.city) {
    callback();
  } else {
    callback(new Error('请选择省市'));
  }
};
```

#### 步骤2：查找对应的统一校验方法
- 手机号校验 → `validationRules.phone`
- 金额校验 → `validationRules.amount`
- 邮箱校验 → `validationRules.email`
- 自定义校验 → 保留或提取为通用方法

#### 步骤3：引入统一校验方法
```javascript
// 改造后：使用统一校验方法
import { validationRules, validatePhone } from '@/api/tool';
```

#### 步骤4：替换校验规则配置
```javascript
// 改造前
rules: {
  relationTel: [
    { required: true, message: '联系人电话不能为空', trigger: 'blur' },
    { pattern: /^1[3-9]\d{9}$/, message: '请输入正确的手机号', trigger: 'blur' }
  ]
}

// 改造后
rules: {
  relationTel: validationRules.phone
}
```

#### 步骤5：移除重复代码
- 删除自定义校验函数
- 清理不需要的校验相关代码

## 5. 扩展和维护

### 5.1 新增校验方法

当需要新增校验方法时，统一在 `@/api/tool/index.js` 中添加：

```javascript
/**
 * 新的校验方法
 * @param {Object} rule - 校验规则
 * @param {String} value - 输入值
 * @param {Function} callback - 回调函数
 */
export const validateNewRule = (rule, value, callback) => {
  // 校验逻辑
  if (!value) {
    return callback(new Error('请输入内容'));
  }
  // 具体校验
  if (/* 校验条件 */) {
    return callback(new Error('校验失败提示'));
  }
  callback();
};

// 同时添加到预设规则中
export const validationRules = {
  // 现有规则...
  newRule: [
    { required: true, message: '请输入内容', trigger: 'blur' },
    { validator: validateNewRule, trigger: 'blur' }
  ]
};
```

### 5.2 修改现有校验方法

```javascript
// 修改校验方法时，只需要在一个地方修改
export const validatePhone = (rule, value, callback) => {
  if (!value) {
    return callback(new Error('请输入手机号'));
  }
  // 更新正则表达式或校验逻辑
  const phoneReg = /^1[3-9]\d{9}$/; // 新的正则
  if (!phoneReg.test(value)) {
    return callback(new Error('请输入正确的手机号码'));
  }
  callback();
};
```

### 5.3 版本管理

- 新增校验方法向后兼容
- 修改现有方法需要考虑影响范围
- 删除方法需要全局搜索使用情况

## 6. 最佳实践

### 6.1 选择合适的使用方式

1. **优先使用预设规则**：对于常见的校验场景
2. **使用单个校验方法**：需要自定义提示信息时
3. **使用工厂函数**：需要参数化校验时
4. **自定义校验**：业务特有的复杂校验逻辑

### 6.2 命名规范

- 校验方法：`validate + 描述`，如 `validatePhone`
- 预设规则：使用简洁的名称，如 `phone`、`email`
- 工厂函数：`validate + 描述 + 参数说明`

### 6.3 错误提示规范

- 使用用户友好的提示信息
- 保持提示信息的一致性
- 避免技术术语

### 6.4 性能考虑

- 避免在校验函数中进行复杂的异步操作
- 缓存正则表达式对象
- 合理使用防抖机制

## 7. 常见问题解决

### 7.1 校验方法不生效

**问题**：导入的校验方法无法正常工作
**解决**：
1. 检查导入路径是否正确
2. 确认方法名是否正确
3. 检查校验规则配置是否正确

### 7.2 自定义校验冲突

**问题**：自定义校验与统一校验冲突
**解决**：
1. 分析校验逻辑是否可以合并
2. 考虑提取为通用校验方法
3. 保持业务特有的自定义校验

### 7.3 提示信息不一致

**问题**：不同页面的提示信息不一致
**解决**：
1. 使用预设规则保证一致性
2. 统一错误提示文案
3. 建立提示信息规范
