## Context

项目基于 Vue 2 和 Element UI，系统内存在大量 `el-table`。当前仓库已经全局引入 `v-fit-columns`，并存在 `FitTable` 组件以及列配置中的 `autoWidth` 处理逻辑，但不同页面仍有大量手工 `width` 配置，导致自动列宽能力未形成统一规范。

该变更属于跨页面、跨组件的表格展示规范调整，需要优先在公共层定义统一行为，而不是在业务页面逐个补丁式处理。

## Goals

- 默认让常规数据列根据表头和内容自动计算宽度。
- 统一自动列宽的生效范围和例外规则。
- 在常见数据变更场景下重新计算列宽。
- 保持固定列、横向滚动、排序和筛选等现有表格行为稳定。

## Non-Goals

- 不要求一次性删除所有历史手工宽度配置。
- 不改造非 Element UI 表格组件。
- 不调整业务字段文案或字段排序规则。

## Decisions

### 1. 优先落在公共表格层

自动列宽应优先接入全局插件、表格封装组件或统一列配置处理层，避免在具体业务页面逐个绑定。业务页面仅在特殊场景下声明例外。

### 2. 常规列默认参与自动列宽

常规数据列默认参与自动列宽计算。选择列、序号列、展开列、操作列以及业务显式声明固定宽度的列，不参与自动拉宽。

### 3. 自动拉宽需要上限和降级策略

自动列宽不能无限制扩张。对于超长内容，应设置最大展示宽度；达到上限后使用省略展示，并依赖现有 tooltip 或悬浮能力查看完整值。

### 4. 列宽重算要覆盖常见交互

以下场景需要重算列宽：
- 首次加载数据
- 搜索或筛选后刷新列表
- 分页切换
- 动态显示或隐藏列
- 表格容器宽度变化

### 5. 总宽度超出容器时保持横向滚动

当自动计算后的总列宽超过容器宽度时，优先保留内容可读性，通过横向滚动承载，而不是强制压缩所有列。

## Risks

- 自动列宽可能与固定列渲染机制产生冲突，导致表头或固定列错位。
- 大表格在频繁重算列宽时可能产生性能问题。
- 历史页面存在较多显式 `width` 配置，统一策略落地时需要明确兼容优先级。

## Open Questions

- 是否需要为特定页面提供关闭自动列宽的开关。
- 宽度上限应采用全局默认值，还是允许按列覆盖。
