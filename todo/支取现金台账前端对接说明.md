# 转 、支现金台账前端对接说明

## 1. 页面与业务约定

- 页面菜单：`销售部奖励制度 / 转 、支现金台账`，位于“其他奖励”之后。
- 后端前缀：`/system/cashWithdrawalLedger`。
- 取现日期只精确到日，请使用 `yyyy-MM-dd`，不要提交时分秒。
- 取现账户由用户手工输入，不关联银行账户，不触发账户流水或资金变动。
- 金额后端类型为 `DECIMAL(28,8)`，必须大于 0，最多 20 位整数和 8 位小数。前端请求建议使用普通十进制数或可被 JSON 正确解析的数值，不要做浮点运算后再提交。
- 审核状态只有 `未审核`、`已审核`。新增时由后端固定为 `未审核`，前端不要传审核人、审核时间或删除状态。
- `已审核`记录完全冻结：不能修改主记录、替换附件、删除记录，也不能修改或删除其引用的附件；需先取消审核。
- 删除为软删除。批量删除只要包含已审核或不存在的记录，整次操作失败。

## 2. 字段说明

| 字段 | 类型 | 新增/修改 | 说明 |
| --- | --- | --- | --- |
| `id` | `number` | 修改必填 | 台账 ID |
| `withdrawalDate` | `string` | 必填 | 取现日期，格式 `yyyy-MM-dd` |
| `amount` | `number` | 必填 | 取现金额，`> 0`，最多 20 位整数和 8 位小数 |
| `accountInfo` | `string` | 必填 | 取现账户名称及账号信息，最多 255 字符，手工输入 |
| `handlerName` | `string` | 必填 | 取现经办人，最多 100 字符 |
| `purpose` | `string` | 必填 | 取现用途，最多 500 字符 |
| `remark` | `string \| null` | 选填 | 备注，最多 500 字符 |
| `auditState` | `string` | 只读 | `未审核`或`已审核` |
| `auditUserId` | `number \| null` | 只读 | 审核人 ID |
| `auditUserName` | `string \| null` | 只读 | 审核人姓名 |
| `auditTime` | `string \| null` | 只读 | `yyyy-MM-dd HH:mm:ss` |
| `attachmentList` | `Attachment[]` | 只读 | 当前关联的完整附件集合 |
| `createByUserName` | `string \| null` | 只读 | 创建人姓名 |
| `createTime` | `string` | 只读 | 创建时间 |
| `updateByUserName` | `string \| null` | 只读 | 最后修改人姓名 |
| `updateTime` | `string \| null` | 只读 | 最后修改时间 |

附件对象主要使用字段：`id`、`fileName`、`filePath`、`fileSuffix`、`flag`、`extraInfo`、`remark`。

## 4. 附件处理

### 4.1 两列附件的 flag

数据库中仍是统一附件表，前端按 `flag` 拆成两列展示：

| 页面列 | `flag` |
| --- | --- |
| 取现审批单、取现小票 | `withdrawalProof` |
| 其他附件 | `otherAttachment` |

本模块只接受以上两个 flag，其他 flag 在新增关联或替换关联时会被后端拒绝。

### 4.2 上传附件

调用通用附件接口：

```http
POST /system/attachments
Content-Type: multipart/form-data
```

表单字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `file` | 是 | 文件二进制 |
| `flag` | 是 | `withdrawalProof` 或 `otherAttachment` |
| `remark` | 否 | 附件备注 |
| `extraInfo` | 否 | JSON 字符串；无额外信息可省略或传 `{}` |

成功后使用 `data.id` 作为附件 ID。上传只创建附件记录，不会自动关联台账。

### 4.3 新增时关联附件

新增接口可在 `params.attachmentIds` 中一次传入已上传附件 ID：

```json
{
  "withdrawalDate": "2026-07-24",
  "amount": 10000.5,
  "accountInfo": "招商银行基本户 12345",
  "handlerName": "张三",
  "purpose": "项目备用金",
  "remark": "可选备注",
  "params": {
    "attachmentIds": [101, 102]
  }
}
```

`params.attachmentIds` 可省略；重复 ID 会去重。

### 4.4 编辑时完整替换附件

主记录修改接口不接受 `params.attachmentIds`。编辑页面保存附件时单独调用：

```http
PUT /system/cashWithdrawalLedger/attachments
Content-Type: application/json
```

```json
{
  "cashWithdrawalLedgerId": 1,
  "attachmentIds": [101, 102]
}
```

这是完整集合替换，不是增量追加：

- 传 `[101, 102]`：最终只关联这两个附件。
- 传 `[]` 或 `null`：清空全部附件关联。
- 前端两列合并出一个 ID 数组再提交，后端根据附件本身的 `flag` 分类。
- 已审核记录调用该接口会失败。

## 5. 业务接口

### 5.1 分页列表

```http
GET /system/cashWithdrawalLedger/list
```

查询参数均为扁平参数，不要放进 `params`：

| 参数 | 说明 |
| --- | --- |
| `pageNum`、`pageSize` | 分页参数 |
| `beginWithdrawalDate` | 开始日期，`yyyy-MM-dd`，包含当天 |
| `endWithdrawalDate` | 结束日期，`yyyy-MM-dd`，包含当天 |
| `accountInfo` | 账户模糊查询 |
| `handlerName` | 经办人模糊查询 |
| `purpose` | 用途模糊查询 |
| `auditState` | 精确匹配 `未审核`或`已审核` |

响应沿用项目 `TableDataInfo`：

```json
{
  "code": 200,
  "msg": "查询成功",
  "total": 1,
  "rows": [
    {
      "id": 1,
      "withdrawalDate": "2026-07-24",
      "amount": 10000.50000000,
      "accountInfo": "招商银行基本户 12345",
      "handlerName": "张三",
      "purpose": "项目备用金",
      "auditState": "未审核",
      "auditUserId": null,
      "auditUserName": null,
      "auditTime": null,
      "remark": null,
      "attachmentList": []
    }
  ]
}
```

列表和详情都会返回 `attachmentList`，前端可按 `flag` 分组。

### 5.2 详情

```http
GET /system/cashWithdrawalLedger/{id}
```

业务对象在 `data` 中；不存在或已删除时 `data` 为 `null`。

### 5.3 新增

```http
POST /system/cashWithdrawalLedger
Content-Type: application/json
```

请求示例见“新增时关联附件”。成功后 `data` 返回已生成 `id` 的记录，状态固定为 `未审核`。

### 5.4 修改主记录

```http
PUT /system/cashWithdrawalLedger
Content-Type: application/json
```

```json
{
  "id": 1,
  "withdrawalDate": "2026-07-25",
  "amount": 12000,
  "accountInfo": "招商银行基本户 12345",
  "handlerName": "李四",
  "purpose": "备用金调整",
  "remark": null
}
```

所有业务必填字段都要完整提交；不要在该请求中传 `params.attachmentIds`。已审核记录修改失败。

### 5.5 删除

```http
DELETE /system/cashWithdrawalLedger/{ids}
```

`ids` 支持逗号分隔，例如 `/system/cashWithdrawalLedger/1,2`。仅未审核记录可删除。

### 5.6 审核与取消审核

```http
PUT /system/cashWithdrawalLedger/audit/{id}?approved=true
```

- `approved=true`：审核，状态变为 `已审核`，后端记录当前用户和时间。
- `approved=false`：取消审核，状态恢复 `未审核`，审核人和审核时间清空。
- 对已审核记录重复审核、对未审核记录重复取消审核都会返回业务错误。
- 建议前端审核/取消审核成功后，用返回的 `data` 直接刷新当前行和附件状态。

### 5.7 导出

```http
POST /system/cashWithdrawalLedger/export
Content-Type: application/x-www-form-urlencoded
```

导出使用与列表相同的筛选字段，但不传分页参数。响应是 XLSX 二进制，不是统一 JSON；请求配置必须使用 `responseType: 'blob'`。示例：

```js
request({
  url: '/system/cashWithdrawalLedger/export',
  method: 'post',
  params: query,
  responseType: 'blob'
})
```

导出列按原始表格固定为：取现日期、取现金额、取现账户名称+账号后5位数、（取现审批单+取现小票)附件、取现经办人、取现用途、附件、审核状态、审核人、备注。附件列导出文件名，多个文件用英文逗号连接。

## 6. 推荐前端保存顺序

新增：先上传两列附件并收集 ID，再调用新增接口一次提交主记录和 `params.attachmentIds`。

编辑：先保存主记录，再把两列当前保留的全部附件 ID 合并后调用附件完整替换接口。任一步返回 `code != 200` 都提示后端 `msg`，不要继续自动审核。

审核后应禁用编辑、附件上传/删除、删除按钮，只保留取消审核和查看/下载能力。
