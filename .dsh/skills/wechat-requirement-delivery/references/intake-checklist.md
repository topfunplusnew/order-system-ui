# 收料清单与归档规范

## 一、最小信息清单（缺哪项就向用户索要哪项）

### A. 需求来源
- [ ] 微信聊天记录：文本 / 截图 / 导出文件（截图必须逐张读图转写）
- [ ] 发言人身份（谁提的需求：业务/客服/老板/客户）与其话语权重
- [ ] 聊天时间范围（多条冲突说法时按最新时间取）

### B. 接口材料
- [ ] 接口文档：APIfox 链接 或 粘贴的文档 或 项目内 openapi 快照
- [ ] 接口地址 / base URL（test、pre、stage 分别是什么）
- [ ] 涉及的接口清单（路径 + 方法），或能定位到哪些接口
- [ ] 鉴权方式（token 放 header 还是 query）、Content-Type

### C. 业务口径
- [ ] 目标页面 / 菜单入口 / 路由
- [ ] 目标环境（只在 test 验证，还是三环境都要）
- [ ] 金额精度：保留几位小数、四舍五入还是银行家舍入
- [ ] 权限范围（哪些角色可见/可操作）
- [ ] 是否需要导出、是否需要打印、是否需要移动端适配

### D. 交付约定
- [ ] 开发分支基线（默认 `order-test`）
- [ ] 分支命名偏好（默认 `feat/YYYYMMDD-<slug>`）
- [ ] 合并目标（默认 `order-stage` / `order-pre` / `order-test`）
- [ ] 合并后是否立即推送（默认：先停，确认后再推）

## 二、归档规范

| 内容 | 落盘位置 |
|---|---|
| 原始聊天记录（转写文本） | `requirements/_raw/YYYY-MM-DD-<主题>.md` |
| 原始截图 | `requirements/_raw/YYYY-MM-DD-<主题>/*.png` |
| 接口文档原文（粘贴/导出） | `requirements/_raw/YYYY-MM-DD-<主题>-接口文档.md` |
| 整理后的需求条目清单 | `requirements/YYYY-MM-DD-<主题>.md` |

归档文件头部必须写：

```markdown
> 来源：微信聊天记录（<群名/联系人>），获取时间 YYYY-MM-DD HH:mm
> 接口文档：<链接或"用户粘贴">，核对时间 YYYY-MM-DD HH:mm
> 涉及环境：test / pre / stage
```

## 三、读图要求

1. 每张截图都调用 `read_image` 实际读一遍，不要推测内容。
2. 转写时保留**需求原话**，包括口语化表述；不要边读边"优化"成需求语言。
3. 截图里出现的字段名、接口路径、数量、金额，逐字抄录，不要顺手纠正拼写。
4. 截图模糊/关键信息被遮挡 → 列入待确认清单，向用户要清晰版或口头说明。
