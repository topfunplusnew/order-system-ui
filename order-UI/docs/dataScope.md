# 本文档用来来解释数据权限每一位的作用

> 目前共20位,使用了4位
>
> 一共20位,每一位是一个数字,后端每次使用时提取角色信息中的本角色的数据权限标识符,并获取对应位的数字,解析后对查询sql进行组装

## 最后一位 部门数据权限

| 对应位的值 | 代表的意思         | 备注 |
| ---------- | ------------------ | ---- |
| 1          | 全部数据权限       |      |
| 2          | 自定数据权限       |      |
| 3          | 部门数据权限       |      |
| 4          | 部门及以下数据权限 |      |
| 5          | 仅本人数据权限     |      |

> 部门数据权限目前仅支持查看用户列表时生效

## 第一位 订单数据权限

| 对应位的值 | 代表的意思            | 备注 |
| ---------- | --------------------- | ---- |
| 1          | 仅能查看自己录入的    |      |
| 2          | 仅自己负责的客户      |      |
| 3          | 1和2的并集            |      |
| 0          | 默认,代表不做任何限制 |      |

## 第二位 company数据权限

| 对应位的值 | 代表的意思             | 备注                                         |
| ---------- | ---------------------- | -------------------------------------------- |
| 1          | 仅能查看自己录入的     |                                              |
| 2          | 仅能查看业务员是自己的 | 后端这里必须保证用户信息中的TrueName是正确的 |
| 3          | 1和2的并集             |                                              |
| 0          | 默认,代表不做任何限制  |                                              |

## 第三位 付款申请数据权限

| 对应位的值 | 代表的意思            | 备注               |
| ---------- | --------------------- | ------------------ |
| 1          | 仅能查看自己录入的    | 后端使用userId锁定 |
| 0          | 默认,代表不做任何限制 |                    |
